clean-chat vs convex-chat

Same Slack-style chat product (docs/PRODUCT.md). Different bets: Convex Chat leans on a managed backend; Clean Chat makes every boundary explicit. Both are learning demos, not production messengers.

Headline
Clean Chat is easier to change, test, and reason about. Convex Chat is harder to break in production because the platform owns transactions, durable auth, live reconnect, and scheduling. Security is split: Clean Chat hardens the HTTP edge; Convex Chat persists credentials and sessions.

Same product constraints
Both apps: any signed-in user sees every channel; author-only delete; no email verification or password reset; React text nodes for messages (no HTML); password min 8 characters, hashed with scrypt; selected channel is React state, not a router.

Convex Chat is operationally sturdier. Clean Chat is more explicit about what happens when input, auth, or a transaction fails — and those behaviors are covered by tests.

Clean Chat ops gap
Auth is still createInMemoryAuth even when chat data is SQLite. A restart or second Node process does not share sessions or password hashes. Convex does not have that split-brain.

Neither app is a hardened messenger. Relative to each other: Clean Chat treats the HTTP edge as a threat surface; Convex Chat treats credential storage and session issuance as a platform problem — and leaves presence list/disconnect weakly authenticated on purpose.

Do not treat either as production auth
No email verification, no password reset, no OAuth, no CSP. Clean Chat tokens in localStorage plus missing CSP is a session-theft story if any XSS appears later. Convex presence list/disconnect are documented shortcuts, not a security boundary.

This is the pillar the port was built to win. Clean Chat encodes the dependency rule in packages. Convex Chat encodes the product in a small, generated-type surface that the UI imports directly.

Coupling

clean-chat UI depends on

@clean-chat/client (Client) and @clean-chat/core (domain constants, events). Not application, not infrastructure.

ClientProvider + live-query hooks call execute and eventSubscriber.subscribe, then re-run the matching query.

convex-chat UI depends on

convex/react, convex/_generated/api, Id<"channels">, ConvexAuthProvider, @convex-dev/presence/react.

Live reads are useQuery. There is no port between React and the backend.

Docs and conventions

Both repos document the product well (PRODUCT.md, ARCHITECTURE.md, AGENTS.md). Clean Chat adds a layer rule, schema-first domain, and JSDoc on ports/use cases. Convex Chat documents what not to copy (api.*, _id, presence tokens) — which is exactly what its UI is built on.

Teaching vs operating
Use Clean Chat to learn (and keep) a dependency rule you can unit-test. Use Convex Chat to ship the same UX with almost no backend of your own. The maintainability win is real; it is also why Clean Chat has ~4× the TypeScript and still weaker auth durability.
